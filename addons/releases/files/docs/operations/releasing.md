# Releasing

The template starts at version `0.1.0` and does not assume a package ecosystem.

Use semantic versioning once the project exposes interfaces that other code or users depend on:

- Use a patch version for a backward-compatible defect fix.
- Use a minor version for a backward-compatible capability addition.
- Use a major version for an intentionally incompatible public contract change.

For pre-1.0 projects, use minor versions to mark meaningful capability or interface milestones and document breaking changes clearly.

A release should correspond to verified behavior, not merely elapsed time.
