# Security hardening

Use this area for project-specific security material that is too detailed for `SECURITY.md`.

Document only what the project actually needs:

- trust and permission boundaries,
- agent/tool capability policy,
- sandboxing or isolation assumptions,
- dependency and supply-chain controls,
- sensitive-data handling,
- audit requirements,
- incident-specific security runbooks.

Keep `THREAT_MODEL.md` as the map of assets, actors, abuse cases, controls, and evidence. Put executable or repeatable adversarial scenarios under `evals/adversarial/`.
